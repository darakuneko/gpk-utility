# Appendix D: Implementation Checklist

A phased checklist for implementing a new GPK Utility-compatible keyboard.

---

## Phase 0: Branch Preparation

- [ ] Cloned `darakuneko/vial-qmk` and switched to the `gpk-utility` branch
- [ ] An existing QMK keyboard definition is placed under `keyboards/<name>/`
- [ ] The build passes (`qmk compile -kb <name> -km default`, etc.)

---

## Phase 1: Build Configuration

### rules.mk (keyboard root)

- [ ] Add `GPKRC_ENABLE = yes`
- [ ] Add `SRC += config/device_config.c`
- [ ] If it has a trackpad: set `POINTING_DEVICE_ENABLE = yes` and an appropriate driver
- [ ] If it has a trackpad: `SRC += config/trackpad_config.c config/pomodoro_config.c timer/pomodoro.c`
- [ ] If LED-capable: `SRC += config/led_config.c`

### keymaps/vial/rules.mk

- [ ] `VIA_ENABLE = yes`
- [ ] `VIAL_ENABLE = yes`
- [ ] When using LED/RGB: `VIALRGB_ENABLE = yes`

### config.h

- [ ] Set `VIAL_KEYBOARD_UID` (generated by the Vial configurator)
- [ ] Set `VIAL_UNLOCK_COMBO_ROWS`, `VIAL_UNLOCK_COMBO_COLS`
- [ ] Set `EECONFIG_USER_DATA_SIZE 128`
- [ ] If it has a trackpad: set `MOUSE_EXTENDED_REPORT`
- [ ] When using DRV2605L: write the haptic settings

---

## Phase 2: device_config Implementation

### 2-A: Minimal (keyboard / keyboard_oled)

- [ ] Create `config/device_config.h`
  - [ ] `id_device_get_value_t` enum (`id_device_get_value = 0x01`)
  - [ ] `id_device_operation_t` enum (`id_layer_move = 0x01`, `id_oled_write = 0x02`)
  - [ ] `id_device_set_value_t`, the struct, and EEPROM functions are not needed
- [ ] Create `config/device_config.c`
  - [ ] `send_device_config()` — hardcode `data[4] = 1`, send device_name
  - [ ] `gpk_rc_handle_command_user()` — get_value → `send_device_config()` / operation → layer_move/oled_write

### 2-B: Full (keyboard_tp / macropad_tp family)

- [ ] Create `config/device_config.h`
  - [ ] `device_config_t` struct definition
  - [ ] `id_device_set_value_t` enum (0x01–0x05)
  - [ ] `id_device_get_value_t` enum (0x01–0x06)
  - [ ] `id_device_operation_t` enum (0x01–0x03 / tp family includes `id_trackpad_temp_apply = 0x03`)
  - [ ] Function prototype declarations
- [ ] Create `config/device_config.c`
  - [ ] `init_device_config()` — set defaults + initialize EEPROM
  - [ ] `save_device_config()` — call `eeconfig_update_user_datablock`
  - [ ] `schedule_device_config_save()` — schedule a delayed save
  - [ ] `check_and_save_device_config()` — run the save after 5000ms elapsed
  - [ ] `send_set_value_complete()` — send ACK
  - [ ] `send_device_config()` — `data[4] = device_config.init`, send device_name
  - [ ] `gpk_rc_handle_command_user()` — dispatch all commands

**Verification**: If CONSOLE_ENABLE is on, command-receive logs are printed in `QMK Toolbox`

---

## Phase 3: Subsystem Implementation

### 3a. trackpad_config (tp family only)

- [ ] Create `config/trackpad_config.h` (struct + prototypes)
- [ ] Create `config/trackpad_config.c`
  - [ ] `init_trackpad_config()` — defaults
  - [ ] `send_trackpad_config()` — send 19 bytes with the bit-packing in Appendix A §3
  - [ ] `receive_trackpad_config()` — receive with the same layout and call `update_trackpad_config`
  - [ ] `update_trackpad_config()` — call `schedule_device_config_save`
  - [ ] `set_trackpad_config()` — initialize runtime variables
  - [ ] Live Apply (`id_trackpad_temp_apply` operation 0x03) — apply 19 bytes to RAM temporarily. Do not call `schedule_device_config_save` or `send_set_value_complete` (non-persistent, no ACK; Appendix A §8)

**Bit-packing check**: The table in Appendix A §3 must match the `send_trackpad_config`/`receive_trackpad_config` implementation

### 3b. pomodoro_config (optional)

- [ ] Create `config/pomodoro_config.h`
- [ ] Create `config/pomodoro_config.c`
  - [ ] `init_pomodoro_config()` — defaults
  - [ ] `send_pomodoro_config()` — send 8 bytes (Appendix A §4)
  - [ ] `send_pomodoro_active_status()` — send 5-byte status
  - [ ] `receive_pomodoro_config()` — receive and apply
  - [ ] `set_pomodoro_config()` — initialize runtime variables
- [ ] Create `timer/pomodoro.h`, `timer/pomodoro.c`
  - [ ] Implement `pomodoro_toggle()`, `pomodoro_update()`, `pomodoro_notify()`

### 3c. led_config (LED-capable devices only)

- [ ] Create `config/led_config.h`
- [ ] Create `config/led_config.c`
  - [ ] `init_led_config()` — set default colors (per the layout in Appendix A §5)
  - [ ] `send_led_config()` — send 18 bytes
  - [ ] `send_led_layer_config()` — send layer_count + RGB
  - [ ] `receive_led_config()`, `receive_led_layer_config()` — receive and apply
- [ ] Implement LED display in `rgb_matrix_indicators_user()`
  - [ ] While `is_pomodoro_flashing()` is true: light all with `get_pomodoro_flash_color()`
  - [ ] Normally: light all with `device_led_config.layer_colors[get_highest_layer(...)]`

---

## Phase 4: Keymap Hook Implementation

- [ ] Define the custom keycode enum (sequential from `QK_KB_0`)
- [ ] The names and order must match `customKeycodes` in `vial.json`
- [ ] Implement `keyboard_post_init_user()`
  - [ ] Read the config with `eeconfig_read_user_datablock`
  - [ ] If `device_config.init` is 0, call `init_device_config`
  - [ ] tp family: initialize the trackpad driver with `init_iqs5xx()`
  - [ ] Apply settings to runtime with `set_trackpad_config`, `set_pomodoro_config`, `set_led_config`
- [ ] Implement `matrix_scan_user()`
  - [ ] Trackpad read loop (tp family only)
  - [ ] `if (timer_active) pomodoro_update();`
  - [ ] `check_and_save_device_config();`
- [ ] Implement custom keycode handlers in `process_record_user()`
  - [ ] `U_POMODR_TGL` → `pomodoro_toggle()`
  - [ ] `U_EEP_CLR` → `eeconfig_init() + init_device_config + soft_reset_keyboard()`
  - [ ] `U_DRAGDROP`, `U_H_SCROLL`, `U_M_ACL_*`, `U_S_ACL_*`, `U_Layer_UP/DOWN`

---

## Phase 5: Recognition Check in GPK Utility

- [ ] Build and flash the firmware
- [ ] Launch GPK Utility (after closing Vial / other HID apps)
- [ ] The device name appears in the top device tabs

**If not recognized, check:**
- Whether the USB Usage Page/Usage is `0xFF60`/`0x61` (is `GPKRC_ENABLE` taking effect?)
- Whether the serial number starts with `vial:` (is `VIAL_ENABLE = yes` enabled?)

---

## Phase 6: Round-Trip Test of Settings

### trackpad_config test

- [ ] Scroll tab: change Scroll Term → confirm the value changes in the FW's uprintf
- [ ] Drag & Drop tab: switching between Term mode / Strength mode is reflected
- [ ] Mouse tab: change Speed → the cursor speed changes
- [ ] Gesture tab: change Tap Term → the gesture sensitivity changes
- [ ] Config Edit Mode: "Apply" a preset → the temporary apply is reflected immediately and disappears on reconnect (or `U_EEP_CLR`) (non-persistent)

### pomodoro_config test

- [ ] Timer tab: change Work Time → start the timer with `U_POMODR_TGL` → phase changes at the configured time
- [ ] Pomodoro progress is shown in the system tray

### led_config test

- [ ] LED tab: change a layer color → the RGB changes (in Solid Color mode)
- [ ] LED tab: change a Pomodoro color → lights in the corresponding color when the timer starts

---

## Phase 7: EEPROM Persistence Verification

- [ ] Change any setting
- [ ] Wait at least 5 seconds (SAVE_DEVICE_CONFIG_TERM = 5000ms)
- [ ] Unplug and replug the device from USB
- [ ] Reconnect in GPK Utility and confirm the changed value is retained
- [ ] `U_EEP_CLR` resets to default values

---

## Phase 8: Auto Layer Feature Check (optional)

- [ ] Layer tab → enable Automatic Layer Switching
- [ ] Launch an app and register it via the "register" button or auto-add
- [ ] Focusing that app automatically switches to the specified layer

> Host-side implementation: `gpkrc-modules/windowMonitoring.ts`
> On Linux, X11 or a GNOME Shell extension (Focused Window D-Bus) is required

## Common Implementation Mistakes

| Mistake | Symptom | Fix |
|---|---|---|
| enum values differ from the host | Settings land in the wrong field | Confirm an exact match with `gpkrc-modules/communication.ts:10-29` |
| Bit-packing order is reversed | Values get garbled | Compare the Appendix A table with the implementation bit by bit |
| Not calling `check_and_save_device_config` | Settings are volatile | Add it to the end of `matrix_scan_user` |
| Forgetting `send_set_value_complete` | The next Set command times out | Always call it at the end of the Set handler |
| Persisting to EEPROM on temp_apply | Live Apply persists and is no longer a trial | For `id_trackpad_temp_apply`, do not call `schedule_device_config_save`/`send_set_value_complete` (Appendix A §8) |
| Confusing `zoom_distance` with `pinch_distance` | The field name differs between host and FW | FW=`zoom_distance`, host=`pinch_distance` are the same value |
| Typo in device_name | The device type becomes `unknown` | Check the string against the list in Appendix B §5 |
