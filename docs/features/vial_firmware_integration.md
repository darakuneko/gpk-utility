## 0. Audience and Prerequisites

**Audience**: Developers who want to make a custom Vial keyboard/trackpad configurable with GPK Utility.

**Prerequisites**:
- Basic knowledge of QMK / Vial firmware
- Use the `gpk-utility` branch of `darakuneko/vial-qmk` — see [§2.1 vial-qmk Branch](#21-vial-qmk-branch) for the clone/checkout steps
- Reference implementation: `https://github.com/darakuneko/keyboard/tree/main/qmk/numnum_bento_max` (macropad_tp_btns type)

**Note**: The app conflicts with other communication software (the Vial app, etc.). Close other apps before launching GPK Utility.

## 1. Architecture Overview

### 1.1 Communication Layers

```
GPK Utility (Electron)
    │
    ├─ Main Process (index.ts)
    │   └─ gpkrc-modules/deviceManagement.ts ── HID read/write
    │
    └─ Preload (preload/device.ts, preload/api.ts)
        └─ Exposes the API to the renderer via IPC

Vial keyboard (QMK)
    └─ raw_hid_receive → gpk_rc_handle_command_user()
```

**HID protocol**:
- Usage Page: `0xFF60`
- Usage: `0x61`
- Packet size: Host→FW 64 bytes / FW→Host 32 bytes
- Leading byte (prefix): `0xFA`

> Host reference: `gpkrc-modules/communication.ts:40-43`

### 1.2 Device Detection Conditions

At startup the app scans connected HID devices and targets those that satisfy:

1. `serialNumber` starts with `"vial:"` (automatically assigned by the Vial firmware)
2. HID Usage Page = `0xFF60`, Usage = `0x61`

> Host reference: `gpkrc-modules/deviceManagement.ts:96-101`

### 1.3 Command System

| command_id | Value | Purpose |
|---|---|---|
| `customSetValue` | `0x01` | Host → FW: write settings |
| `customGetValue` | `0x02` | Host → FW: request to read settings |
| `gpkRCOperation` | `0x03` | Host → FW: layer_move / oled_write / trackpad_temp_apply |

| action_id (Set) | Value | Target |
|---|---|---|
| `setValueComplete` | `0x01` | FW → Host ACK |
| `trackpadSetValue` | `0x02` | Trackpad settings |
| `pomodoroSetValue` | `0x03` | Pomodoro settings |
| `ledSetValue` | `0x04` | LED settings |
| `ledLayerSetValue` | `0x05` | LED layer settings |

| action_id (Get) | Value | Target |
|---|---|---|
| `deviceGetValue` | `0x01` | Device identification info |
| `trackpadGetValue` | `0x02` | Trackpad settings |
| `pomodoroGetValue` | `0x03` | Pomodoro settings |
| `pomodoroActiveGetValue` | `0x04` | Pomodoro running status |
| `ledGetValue` | `0x05` | LED settings |
| `ledLayerGetValue` | `0x06` | LED layer settings |

| action_id (Operation) | Value | Purpose |
|---|---|---|
| `layerMove` | `0x01` | Layer switch |
| `oledWrite` | `0x02` | OLED text write |
| `trackpadTempApply` | `0x03` | Temporary apply of trackpad settings (Live Apply, non-persistent) |

> Host reference: `gpkrc-modules/communication.ts:2-29`

## 3. device_config (Core Implementation)

Required for all device_types. The implementation splits into two patterns: **minimal** (`keyboard`, `keyboard_oled`) and **full** (`keyboard_tp`, `macropad_tp_btns`).

### 3.1 device_config.h

**Minimal (keyboard / keyboard_oled)** — no struct/EEPROM needed:
```c
#pragma once
#include "gpk_rc.h"
enum id_device_get_value_t { id_device_get_value = 0x01 };
enum id_device_operation_t { id_layer_move = 0x01, id_oled_write = 0x02 };
```

**Full (keyboard_tp / macropad_tp family)**:
```c
#pragma once
#include "gpk_rc.h"
#include "trackpad_config.h"
#include "pomodoro_config.h"
#include "led_config.h"
#define SAVE_DEVICE_CONFIG_TERM 5000
typedef struct {
    bool init : 1;
    trackpad_config_t trackpad_config;
    pomodoro_config_t pomodoro_config;
    device_led_config_t led_config;
} device_config_t;
extern device_config_t device_config;
```

### 3.2 enum Definitions — Full Configuration Only (the minimal config only needs the 2 enums in §3.1)

```c
enum id_device_set_value_t {
    id_set_value_complete   = 0x01,
    id_trackpad_set_value   = 0x02,
    id_pomodoro_set_value   = 0x03,
    id_led_set_value        = 0x04,
    id_led_layer_set_value  = 0x05
};

enum id_device_get_value_t {
    id_device_get_value          = 0x01,
    id_trackpad_get_value        = 0x02,
    id_pomodoro_get_value        = 0x03,
    id_pomodoro_active_get_value = 0x04,
    id_led_get_value             = 0x05,
    id_led_layer_get_value       = 0x06
};

enum id_device_operation_t {
    id_layer_move          = 0x01,
    id_oled_write          = 0x02,
    id_trackpad_temp_apply = 0x03   // Live Apply: temporary RAM apply (non-persistent) — tp family only
};
```

> Host reference: `gpkrc-modules/communication.ts:10-29`

### 3.3 EEPROM Persistence (device_config.c) — keyboard_tp / macropad_tp family only

```c
device_config_t device_config;
static bool save_pending = false;
static uint32_t save_timer = 0;
static device_config_t pending_config;

void init_device_config(device_config_t *cfg) {
    eeconfig_init_user_datablock();
    init_trackpad_config(&cfg->trackpad_config);  // tp family only
    init_pomodoro_config(&cfg->pomodoro_config);
    init_led_config(&cfg->led_config);            // LED-capable devices only
    cfg->init = 1;
    save_device_config(*cfg);
}

void save_device_config(device_config_t cfg) {
    eeconfig_update_user_datablock(&cfg, 0, sizeof(cfg));
}

void schedule_device_config_save(device_config_t cfg) {
    pending_config = cfg;
    save_timer = timer_read32();
    save_pending = true;
}

void check_and_save_device_config(void) {
    if (save_pending && timer_elapsed32(save_timer) >= SAVE_DEVICE_CONFIG_TERM) {
        save_device_config(pending_config);
        save_pending = false;
    }
}
```

> Reference: [numnum_bento_max/config/device_config.c:8-39](https://github.com/darakuneko/keyboard/blob/main/qmk/numnum_bento_max/config/device_config.c#L8-L39)

### 3.4 gpk_rc_handle_command_user() (device_config.c)

With `GPKRC_ENABLE = yes`, this is called automatically from `raw_hid_receive`.

**Minimal (keyboard / keyboard_oled)** — get_value always returns `send_device_config()` regardless of action:
```c
void gpk_rc_handle_command_user(uint8_t id, uint8_t action, uint8_t *data, uint8_t length) {
    if (id == id_gpk_rc_get_value)        send_device_config();
    else if (id == id_gpk_rc_operation) {
        if (action == id_layer_move) layer_move(data[0]);
#ifdef OLED_ENABLE
        else if (action == id_oled_write && is_oled_on()) oled_write((const char*)data, false);
#endif
    }
}
```

**Full (keyboard_tp / macropad_tp family)**:
```c
void gpk_rc_handle_command_user(uint8_t id, uint8_t action,
                                uint8_t *data, uint8_t length) {
    if (id == id_gpk_rc_set_value) {
        if (action == id_trackpad_set_value) {
            receive_trackpad_config(data);
            send_set_value_complete();
        } else if (action == id_pomodoro_set_value) {
            receive_pomodoro_config(data);
            send_set_value_complete();
        } else if (action == id_led_set_value) {
            receive_led_config(data);
            send_set_value_complete();
        } else if (action == id_led_layer_set_value) {
            receive_led_layer_config(data);
            send_set_value_complete();
        }
    } else if (id == id_gpk_rc_get_value) {
        if (action == id_device_get_value)          send_device_config();
        if (action == id_trackpad_get_value)        send_trackpad_config(&device_config.trackpad_config);
        if (action == id_pomodoro_get_value)        send_pomodoro_config(&device_config.pomodoro_config);
        if (action == id_pomodoro_active_get_value) send_pomodoro_active_status(&device_config.pomodoro_config);
        if (action == id_led_get_value)             send_led_config(&device_config.led_config);
        if (action == id_led_layer_get_value)       send_led_layer_config(&device_config.led_config);
    } else if (id == id_gpk_rc_operation) {
        if (action == id_layer_move) {
            layer_move(data[0]);
        } else if (action == id_oled_write) {
#ifdef OLED_ENABLE
            if (is_oled_on()) oled_write((const char *)data, false);
#endif
        } else if (action == id_trackpad_temp_apply) {
            // Live Apply (Config Edit Mode "Apply"): parse the same 19-byte trackpad
            // payload as id_trackpad_set_value and apply it to the running config for
            // live preview, but RAM only:
            //   - do NOT call schedule_device_config_save() (no EEPROM persist)
            //   - do NOT call send_set_value_complete()    (no ACK; operation command)
            // The host does not wait for an ACK; it reads back via id_trackpad_get_value
            // and retries until the values match.
            apply_trackpad_config_temp(data);   // apply to RAM without persisting
        }
    }
}
```

> `apply_trackpad_config_temp()` parses the same 19 bytes as `receive_trackpad_config()`
> and applies them to the running `trackpad_config`, differing only in that it does not call
> `schedule_device_config_save()` or `send_set_value_complete()` (packet details: Appendix A §8).

> Reference: [numnum_bento_max/config/device_config.c:61-102](https://github.com/darakuneko/keyboard/blob/main/qmk/numnum_bento_max/config/device_config.c#L61-L102)

### 3.5 send_device_config() — Device Identification

```c
void send_device_config(void) {
    uint8_t data[32] = {0};
    data[0] = id_gpk_rc_prefix;
    data[1] = id_gpk_rc_get_value;
    data[2] = id_device_get_value;
    data[3] = 1;                        // protocol version
    data[4] = device_config.init;       // init flag

    // String that determines device_type — controls what GPK Utility displays
    const char device_name[] = "macropad_tp_btns";  // ← change to match your device ("macropad_tp" is also valid)
    memcpy(&data[5], device_name, sizeof(device_name));
    raw_hid_send(data, sizeof(data));
}

void send_set_value_complete(void) {
    uint8_t data[32] = {0};
    data[0] = id_gpk_rc_prefix;
    data[1] = id_gpk_rc_set_value;
    data[2] = id_set_value_complete;
    raw_hid_send(data, sizeof(data));
}
```

> **Minimal (keyboard_oled)**: hardcode `data[4] = 1` — do not reference `device_config.init`.

**device_name selection guide** (→ see Appendix B):
- Keyboard only: `"keyboard"` (`"macropad"` is also valid)
- Keyboard with OLED: `"keyboard_oled"`
- With trackpad: `"keyboard_tp"` / `"macropad_tp_btns"` (`"macropad_tp"` is also valid)

> Reference: [numnum_bento_max/config/device_config.c:49-58](https://github.com/darakuneko/keyboard/blob/main/qmk/numnum_bento_max/config/device_config.c#L49-L58)

### 4.3 led_config (LED-capable devices only)

Targets: `macropad_tp_btns`, `macropad_tp`, `keyboard_tp` only.

Structure of `device_led_config_t`:
- `layer_colors[9]` — RGB per layer (up to 9 layers)
- `layer_count` — actual number of layers
- `pomodoro_colors` — RGB for work/break/long_break
- `indicator_colors` — RGB for the speed/step/h_scroll indicators

**Required functions**:
- `init_led_config(device_led_config_t *)` — set default colors
- `send_led_config(const device_led_config_t *)` — send 18 bytes
- `send_led_layer_config(const device_led_config_t *)` — send layer_count + RGB
- `receive_led_config(uint8_t *)`, `receive_led_layer_config(uint8_t *)` — receive and apply

The actual LED indicator display is implemented in `rgb_matrix_indicators_user()`.
- While `is_pomodoro_flashing()` is true: flash with `get_pomodoro_flash_color()`
- Normally: light all with `device_led_config.layer_colors[current_layer]`

> Reference: [numnum_bento_max/config/led_config.h](https://github.com/darakuneko/keyboard/blob/main/qmk/numnum_bento_max/config/led_config.h), `led_config.c`

### 5.1 keyboard_post_init_user

```c
void keyboard_post_init_user(void) {
    // Read config from EEPROM
    eeconfig_read_user_datablock(&device_config, 0, sizeof(device_config));

    // Initialize the trackpad driver (tp family only)
    init_iqs5xx();
    wait_ms(300);

    // If uninitialized, initialize with defaults and save
    if (!device_config.init) {
        init_device_config(&device_config);
    }

    // Apply settings to runtime
    set_trackpad_config(device_config.trackpad_config);  // tp family only
    set_pomodoro_config(device_config.pomodoro_config);
    set_led_config(device_config.led_config);             // LED-capable devices only
}

enum {
    U_Layer_UP = QK_KB_0,
    U_Layer_DOWN,
    U_M_ACL_2x, U_M_ACL_4x, U_M_ACL_HALF, U_M_ACL_QUARTER,
    U_M_ACL_UP, U_M_ACL_DOWN,

    U_DRAGDROP,
    U_POMODR_TGL,
    U_EEP_CLR,
    U_H_SCROLL
};

bool process_record_user(uint16_t keycode, keyrecord_t *record) {
    switch (keycode) {
        case U_POMODR_TGL:
            if (record->event.pressed) pomodoro_toggle();
            return false;
        case U_EEP_CLR:
            if (record->event.pressed) {
                eeconfig_init();
                init_device_config(&device_config);
                soft_reset_keyboard();
            }
            return false;
        case U_DRAGDROP:
            if (record->event.pressed) use_drag = !use_drag;
            return false;
        case U_H_SCROLL:
            if (record->event.pressed) {
                use_horizontal_scrolling = !use_horizontal_scrolling;
            }
            return false;
        // ... other keycodes ...
        default:
            return true;
    }
}
```

## 7. Verification Procedure

1. **Device recognition**: Launch GPK Utility → the device name appears in the top tabs
2. **Settings load**: Open each tab and confirm the firmware default values are shown
3. **Settings save**: Change a slider → confirm it is reflected on the device (verify with uprintf when CONSOLE_ENABLE is on)
4. **EEPROM persistence**: After changing a setting, wait 5 seconds, reconnect the device, and confirm the same value is loaded
5. **EEPROM Clear**: Press the `U_EEP_CLR` key to return to default values
6. **Auto Layer**: Configure automatic layer settings in the Layer tab and confirm the layer changes when switching apps
7. **Pomodoro**: Configure the timer → start it with `U_POMODR_TGL` → progress is shown in the tray menu

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Device not recognized | Serial number does not start with `vial:` | Confirm VIAL_ENABLE is set correctly |
| Device not recognized | Usage Page / Usage mismatch | Confirm `GPKRC_ENABLE = yes` is enabled |
| Settings not reflected | `gpk_rc_handle_command_user` is not called | Confirm `GPKRC_ENABLE = yes` and that `device_config.c` is in SRC |
| Not saved to EEPROM | `check_and_save_device_config` is not called | Add it to `matrix_scan_user` |
| Settings reset at startup | `EECONFIG_USER_DATA_SIZE` is too small | Set it to 128 or larger |
| LED tab does not appear | device_name is invalid | Set it to one of `"macropad_tp_btns"`, `"keyboard_tp"` |
| Conflicts with Vial | Multiple apps use HID at the same time | Close Vial before launching GPK Utility |
